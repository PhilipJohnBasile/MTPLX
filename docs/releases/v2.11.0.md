# MTPLX 2.11.0

Faster Flash-Next decode at every context, smooth streaming in the copy lane, and the 27B flash-decoding verify route on by default.

## Flash-Next: the speed lane ships on (PR #391 by @davidtai)

The compiled fixed-M4 verifier, batched target distributions, compiled MTP prepare, relaxed draft ties and the fused K/V gather are now the family defaults for the Qwen3.8-Flash-Next geometry, together with a 32-row rows-gather fence and FR-Spec drafting on packs whose lm_head carries the Q8 group-64 layout it needs. Measured against 2.10.2 on the same hour, copy lane on in both arms, at temperature 1:

| Context | round time | tok/s |
|---|---|---|
| 16k (1,024 generated) | -12% | 52.6 to 60.3 |
| 100k | -18.5% | 47.5 to 51.8 |
| 206k | -14% | 32.2 to 44.2 |

A per-request memory gate keeps the compiled lane off prompts whose bank promotion would not fit (on a 128 GB machine that is roughly the last 20% of the context window); such requests run the plain verify with the rest of the defaults. Every knob still honors an explicit export, including `=0`. Operator belt: `MTPLX_QWEN4_FIXED_M4_MAX_CONTEXT`.

## Smooth streaming in the copy lane

When the model re-emits a previous answer (edit a file, change a color), the context-copy lane commits blocks of 24 tokens per round. The app's typewriter used to paste each block whole and then wait for the next round: two lines, a freeze, two lines. The typewriter now rates arrivals over a wall-clock window and types each block across the round, carrying a few characters into the next one. On the same two-turn flow the copy turn went from 65-character pastes at the 95th percentile to 25, with the longest on-screen pause down from 767 ms to 233 ms. The engine no longer replays the recurrent state after a fully accepted block, and the Route Tape now records every copy-lane round on this family.

## 27B: flash-decoding verify route on by default

The TensorOps flash-decoding verify walk (`MTPLX_NAX_FLASH_ROUTE`) is on in the turbo profile for the dense Qwen3.8-27B family, with its dim-split block defaults from the 72.7k and 128k sweeps (+16% decode at 88k in the receipts). `MTPLX_NAX_FLASH_ROUTE=0` restores the previous route.

## Also in this release

- The OpenAI endpoint accepts the off-ish `reasoning_effort` values some clients send (PR #433 by @sypsyp97).
- A vendored Steel sparse-GQA prefill consumer for M3 machines ships as an opt-in native extension (PR #423 by @humanrouter); it is not built into the app bundle yet.
- The app publishes its decode chip only when the reading changes, slows the metrics snapshots to 500 ms while a turn streams, and no longer schedules a redundant auto-scroll task, which removes several whole-transcript re-evaluations per second during generation.
- StreamScope gained a two-turn copy-lane arm so the streaming gate covers block-sized emits.
